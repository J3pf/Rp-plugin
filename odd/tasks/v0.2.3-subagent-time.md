# Feature: Consistent Epoch Millisecond Timestamps (Rp-plugin v0.2.3)
Garantizar que todos los timestamps emitidos por el plugin sean milisegundos epoch enteros de un único reloj consistente.
Branch: `fix/subagent-timestamps` | Status: completed

## Specs
- S1 (T1: Timestamp Normalization): Every timestamp the plugin emits (`startedAt`, `endedAt`, any `at`/`ts`) must be integer epoch milliseconds from ONE clock. Only trust `ev.occurredAt` (or external numeric times) if it is a plausible epoch ms (finite, integer after `Math.round`, within `[2020-01-01, now + 5 min]`); otherwise use `now` (`Date.now()`). Apply `Math.round` to all timestamps. `durationMs` must be the rounded difference of two values from the same clock, never negative (`Math.max(0, ...)`). If the source provides its own non-negative duration, prefer it (rounded).
- S2 (T2: Plugin-Wide Audit): Search the entire codebase for external numeric time forwarding (`occurredAt`, `timestamp`, `performance.now`, `hrtime`) into the protocol/relay messages, apply the normalization rule, and document the findings.
- S3 (T3: Unit and Integration Tests): Test that `occurredAt = 47725510.340108` (`performance.now()`) resolves to an integer within `[before, after]` `Date.now()`; valid epoch `occurredAt` is preserved (rounded); `durationMs` is never negative; and test end-to-end through the relay message the plugin sends.
