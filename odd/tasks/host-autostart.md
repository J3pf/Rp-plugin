# Feature: Host Autostart & Self-Healing across Operating Systems (Rp-plugin v0.2.2)
Asegurar que sin importar el sistema operativo el host de RP siempre se levante solo y se auto-repare.
Branch: `feat/host-autostart` | Status: completed

## Specs
- S1 (H1: Stable Node Path & Stale Detection): In `src/host/service.ts`, resolve a stable node path from `process.env.PATH` (or non-versioned binary) instead of `process.execPath` (which resolves symlinks to versioned paths like `/Cellar/node/26.0.0/bin/node` on Homebrew). Provide stale unit detection checking if installed service node path or script path is missing, dead, or pointing to a versioned Cellar path.
- S2 (H2: Windows Task Scheduler via XML): Generate valid Task Scheduler XML 2.0 for `rp-host` with `<ExecutionTimeLimit>PT0S</ExecutionTimeLimit>`, `<RestartOnFailure>` with `<Interval>PT1M</Interval>` and `<Count>999</Count>`, `<StartWhenAvailable>true</StartWhenAvailable>`, `<DisallowStartIfOnBatteries>false</DisallowStartIfOnBatteries>`, `<StopIfGoingOnBatteries>false</StopIfGoingOnBatteries>`, `<MultipleInstancesPolicy>IgnoreNew</MultipleInstancesPolicy>`, hidden window, per-user non-admin logon trigger. Install via `schtasks /Create /XML <temp-file> /TN rp-host /F`.
- S3 (H3: Linux systemd --user Service): Add `StartLimitIntervalSec=0` to `[Unit]` so `Restart=always` never gives up. Add `Environment="PATH=..."` captured at install time to `[Service]` so host finds `pi`, `herdr`, `tmux`. In `installService`, check `loginctl show-user $USER -p Linger`, attempt `loginctl enable-linger $USER` if off, and report status.
- S4 (H4: macOS launchd Agent): Set `EnvironmentVariables` with `PATH` captured at install time, `ThrottleInterval` (5s), `StandardOutPath` and `StandardErrorPath` logs under `~/Library/Logs/rp-host.log`. Use `launchctl bootstrap gui/$UID <plist>` and `launchctl kickstart -k gui/$UID/dev.j3pf.rp-host` (not deprecated `load`).
- S5 (H5: Self-Healing & Doctor): Pi extension (`src/extension/index.ts`) ensures the host on every Pi `session_start`: if service is not installed, stale, or not running, automatically (re)install and/or start it non-blocking, never failing Pi, rate-limited (once per 10 min), with opt-out config/flag (`autoHost: false` / `--rp-no-auto-host`). Add `rp-host doctor` CLI command printing per-OS status (installed, enabled, running, node path valid, linger/battery settings) with non-zero exit on problems.
- S6 (H6: Unit Tests & Real Linux Verification): Unit tests for generated systemd unit, launchd plist, Task XML, stale-path detection, self-heal decision table with injected runners, and `rp-host doctor`. Real verification on this Linux machine: `systemctl --user cat rp-host.service` shows stable node path + PATH env, `systemctl --user is-active rp-host` = active, and `systemctl --user kill rp-host` recovers to active within 10s.
- S7 (Docs & Version Bump): Update `INSTALACION.md` and `README.md` per OS. Bump package version to `0.2.2`.
- S8 (Gate & Delivery): Full test suite + typecheck + build. Report `[PLUGIN v0.2.2 — READY FOR REVIEW]` with HEAD, log main..HEAD, counts, real Linux check output. NO push/tag/release until `[PLUGIN v0.2.2 — OK TO PUBLISH]`.
