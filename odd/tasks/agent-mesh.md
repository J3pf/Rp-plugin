# Feature: Agent Mesh (CommEvent) en rp-plugin
Implementación coordinada con Rp-relay y Rp-app bajo ODD para visualización de Agent Mesh.
Branch: `feat/agent-mesh` | Status: in_progress

## Specs
- S1: Schema: add `CommEvent` to `src/shared/protocol.ts` + contract test. Wire contract: `{ type: "comm", commId: "<ULID>", direction: "out" | "in", channel: "intercom" | "orchestrator", action: "send" | "ask" | "reply" | "handover" | "message", peer: { sessionId: string | null, name: string | null, cwd: string | null, ref: string | null }, messageId: string | null, replyTo: string | null, expectsReply: boolean, text: string | null, truncated: boolean, delivered: boolean | null, at: number }`. Add `"comm"` to `hello.plugin.features`.
- S2: OUTGOING: on `tool_execution_start` of tool `intercom` with action ∈ {send, ask, reply, handover} emit comm direction "out" (ask → expectsReply:true; peer.ref = args.to; text = args.message; replyTo = args.replyTo); on the matching `tool_execution_end` emit THE SAME commId again with delivered (`details.delivered / !details.error`) and messageId (`details.messageId`). Ignore list/list-cwd/status/pending/cancel/reply-without-message. Also tool `orchestrator_send_message` → channel "orchestrator", action "message", peer.ref = recipient_session_id. For `reply`, fill peer.sessionId/name/cwd from the inbound message being answered (track inbound messageId → from).
- S3: INCOMING: pi-intercom 0.17.1 (index.ts:1298) injects inbound messages via `pi.sendMessage({ customType:"intercom_message", details:{ from:{id,name,cwd}, message:{ id, expectsReply, replyTo?, ... }, bodyText } })`. Detect that custom message from the Pi event that surfaces it (e.g. `message_end` with a custom role/customType) and emit comm direction "in" with peer.sessionId = from.id, name, cwd, messageId = message.id, expectsReply, replyTo, text = bodyText. Deduplicate (no double emission on re-render/resync).
- S4: Robustness: zero behavior change when pi-intercom is not installed; never throw from the hooks; truncate text to 2000 chars with truncated:true; respect redactContent (text:null); comm passes through the existing bounded queue/reconnect path (not coalesced away).
- S5: Verify that `subagent_update` keeps flowing for subagents launched by this session (the graph shows them as satellites) and that `agent.status` detail reflects the current activity; fix gaps if any.
- S6: Tests: unit tests for out start/end upsert, reply peer fill, orchestrator_send_message, inbound detection, redaction, truncation, intercom absent; fixtures regenerated (`npm run fixtures`) and aligned with relay's fixtures; `npm run typecheck && npm run build && npm run test:unit` green (and e2e if tmux is available).
- S7: Docs: README "What it does" table + PLAN-PLUGIN status (existing doc language, Spanish).
- S8: Delivery: when green → merge to main, bump version (minor, 0.2.0), build the tgz with `npm pack`, tag, PUSH main+tags, PUBLISH a GitHub release with the .tgz attached, and fix the README install URL so it points to the new version.
